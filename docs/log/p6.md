# P6 — Quote accept/reject, receipts, quote expiry (PLAN.md §15.5 J4b/J12, §15.8)

Sonnet, wave 1 lane 2, phase 4 of the sequential `sonnet-wave1-lane2.md` run.
Branch `phase/p6` off `main` at `d5c2db4` (P5).

## Built

- **Quote accept/reject**: `/q/[token]` gains a name + optional comment form
  when `status === "sent"`; `quoteAcceptances` (new, unique index on
  `quote_id`) records the decision once; `modules/quotes/public.ts`'s
  `decideQuote` rate-limits by IP, guards status (`expired`/already-decided/
  not-sent), sets the quote's status, writes a generic `system` activity
  (`quote_accepted`/`quote_rejected`), and emits `quote.accepted`/
  `quote.rejected` — the former already wired to automations by P1.
- **Receipts**: `document_payments.receipt_number`/`receipt_public_token`
  (lazily assigned on first request, via the widened `NumberedDocumentType`
  vocabulary and the existing per-tenant `document_sequences`); `/r/[token]`
  and `/r/[token]/pdf` public views; "Recibo" and "Enviar por WhatsApp"
  buttons on each payment row in `/documents/[id]`.
- **Quote expiry**: `quotes.expire` daily self-rescheduling job
  (`modules/quotes/expiry.ts` + `jobs.ts`, seeded in
  `worker/maintenance.ts`) sweeps every tenant's `sent` quotes past
  `validUntil` to `expired`; the quote page offers "Duplicar como nuevo
  borrador" for an expired quote instead of reviving it.

## Decisions and deviations

1. **A receipt is not a `documents` row.** It renders directly off one
   `document_payments` row — no items, no quote link, no ledger of its own —
   so `documents.type`'s DB enum stays untouched; only the TS-level
   `NumberedDocumentType` widened to cover `"recibo"`.
2. **No new `ActivityType`.** `quote_accepted`/`quote_rejected` are generic
   `system` activities with `payload.kind`, the same escape hatch P1 and P4
   used — `crm/activities.ts`'s enum is outside this phase's Owns column.
3. **`quote.rejected` has no listener yet.** P1 only declared
   `quote_accepted` as a trigger type; the event exists so a future phase can
   wire it without a second migration.
4. **The unique index on `quote_acceptances.quote_id` is the real guard**,
   not the status check — `decideQuote` still checks status first (cheaper,
   clearer error), but a caught insert conflict is what actually stops two
   concurrent tabs from both deciding.
5. **`duplicateQuote` always creates a fresh draft**, never revives the
   expired one — an expired quote's prices and validity are exactly what
   needed a second look.
6. **`worker/maintenance.ts` and `worker/index.ts` touched again** (P1/P2/P4
   precedent) to seed and import the new job chain — a few lines, not a
   rewrite.

## Known issues

- `expireQuotes` walks every tenant on the platform once a day; fine at
  current scale, would want a per-tenant cursor or batching if the tenant
  count grows by orders of magnitude.
- The public accept/reject form has no CAPTCHA — the per-IP rate limit
  (10/min) is the only abuse guard, same posture as the existing `/q/[token]`
  view-rate-limit.
