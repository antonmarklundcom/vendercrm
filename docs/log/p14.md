Sonnet, wave 2 lane 2, phase 2 of the sequential `sonnet-wave2-lane2.md` run.
Branch `phase/p14` off `main` at `00858e4` (P13 + its index line).

## Built

- **`modules/coach/narrative.ts`** (pure, unit-tested): `templateNarrative`
  (deterministic Spanish voseo text every tenant gets, built straight from
  the metric set) and `verifyNarrative` (every `citedMetrics` key must exist
  and every number in the model's prose must be one of the input's own
  metric values — the post-check that keeps hallucinated numbers out).
- **`modules/coach/briefing.ts`**: `buildBriefingInput` (this week vs last
  week via `getSalesReport`, current Hoy counts by kind, the business
  profile's display name); `generateBriefing` tries `generateStructured`
  when AI is configured and the tenant's daily cap allows, verifies the
  result, and falls back to the template on any failure (invented number,
  unknown cited key, a thrown error, the cap, or no driver) — a ledger row
  is written on every provider call either way; `createWeeklyBriefing`
  stores the row, idempotent on the `(tenant_id, week_start)` unique index.
- **`modules/coach/briefing-jobs.ts`**: `coach.weekly`, hourly
  self-rescheduling like `coach.morning` (docs/log/p7.md decision 1) — acts
  on tenants whose local clock reads Monday 07:xx. Delivery: one
  `notifications` row + email per admin, WhatsApp only when the tenant's
  synced templates already contain `briefing_semanal`, sent to the contact
  matching the connected WhatsApp number's own `displayNumber`.
- **Hoy-action instrumentation** (§17.5): the dashboard panel's action links
  and the morning push's link now go through `/dashboard/hoy-redirect`,
  which writes one `coach.hoy_action` audit row (kind, severity, origin
  `panel`/`push`) before redirecting to the real destination.
- **Dashboard**: a briefing card (latest narrative + recommendations, link
  to the full list) under the Hoy panel when one exists; `/dashboard/
  briefings` (list) and `/dashboard/briefings/[id]` (detail).
- **Schema**: `coach_briefings` (migration 0036); `ai_replies.kind` widened
  with `weekly_briefing` (no ALTER — varchar enum, §10 1W precedent).

## Decisions and deviations

1. **Hoy counts are read "now," at job time, not reconstructed for the
   week.** There's no historical snapshot table to read "how many deals
   were stale each day this week" from, so the briefing's stale/unreplied/
   unanswered counts are Monday morning's live Hoy state — documented as a
   known issue, not silently approximated as something more precise.
2. **`generateBriefing` always builds the full input first**, even when AI
   is off or the cap is already hit — the template needs the same metrics,
   so there's no cheaper path to skip to.
3. **"The tenant's contact-number conversation"** (the phase prompt's
   phrase for the WhatsApp copy's recipient) is read as: the contact whose
   phone matches the connected `wa_accounts.displayNumber` — the business
   messaging itself, the same way any other contact is reached. No such
   contact existing is a normal, silent skip, not an error.
4. **The morning push's link now deep-links to the top-ranked Hoy item**
   (`coach/jobs.ts`, in this phase's Owns column) instead of a generic
   `/dashboard`, routed through the same tracked redirect the dashboard
   panel uses — required for §17.5's "push" origin to ever fire at all.
5. **No new AI driver method** — `generateStructured` already exists (K1);
   this phase only adds a schema and a system prompt for it.

## Known issues

- `/dashboard/hoy-redirect` calls `requireTenantContext()`, which throws
  (rather than redirecting to `/login`) if a push notification is tapped
  after the session has expired — same posture as every other route handler
  in this repo that assumes an authenticated tap, not a graceful 401 page.
- The WhatsApp `briefing_semanal` template is never submitted by this
  phase — an admin has to create and get it approved in Meta first, exactly
  as the L2 spec assumes; until then the WhatsApp copy is silently skipped.
- `sendWeeklyBriefings` iterates every tenant on the platform once an hour,
  same posture (and same scaling caveat) as `sendMorningDigests` already has.
