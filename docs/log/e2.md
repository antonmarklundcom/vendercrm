# E2 + E3 — Inbound pipeline, storage and threading (PLAN-EMAIL.md §4)

Opus. Stacked on E1 (branch `phase/email-e2`, PR based on the E1 branch).
Still ships dark: nothing is received until the env vars, the Worker and a
mailbox address exist and the business has the mailbox switched on.

## Built

- **Worker** `workers/email-inbound/` (own `package.json`, `tsconfig.json`,
  `wrangler.toml`; excluded from the Next build, root tsconfig and eslint).
  `email()` stores the raw `.eml` in R2 *first*, parses with `postal-mime`,
  stores each attachment, writes `payload.json`, then POSTs the parsed JSON to
  `/api/v1/email/inbound` signed with HMAC-SHA256 over `timestamp.body`.
  If the POST fails, a marker goes to `email-inbound-pending/` and a cron
  (every 5 min) retries with backoff (5 min → 6 h) for 72 h; after that the
  marker moves to `email-inbound-failed/` and the raw mail stays in R2.
  Once the raw mail is in R2 it is never dropped.
- **Route** `POST /api/v1/email/inbound` → `modules/mailbox/inbound.ts`:
  404 when the mailbox isn't configured on the platform, 401 bad/stale
  signature (5-minute window, constant-time compare), 400 malformed payload,
  202 no active mailbox / business switched off (discarded), 503 business
  read-only (Worker retries), 200 stored or duplicate. No bodies or secrets
  are logged.
- **Tables** (migration `0044_add_mailboxes`, all with `tenant_id`):
  `mailboxes` (address unique platform-wide, domain, display name, catch-all,
  active), `email_threads`, `email_messages` (unique `(tenant_id,
  message_id)` = idempotency key), `email_attachments`.
- **Ingest** (`modules/mailbox/ingest.ts`): copies the Worker's files to
  `email/<tenantId>/<messageId>/…` (the layout tenant purge sweeps — `email`
  added to `STORAGE_KINDS`), deletes the originals, stores the message and
  attachments in one transaction. Concurrent duplicates resolve to the
  winner's row.
- **Threading**: `In-Reply-To`/`References` first, then same mailbox + same
  sender + normalized subject (Re/RV/Fwd/Sv/AW… stripped) within 14 days,
  else a new thread.
- **Contact link**: the sender is linked to an existing contact with that
  email address.
- **HTML**: sanitized server-side before storage (`sanitize-html`): no
  scripts, handlers, forms, iframes, styles that load URLs; remote images
  blocked (`src` → `data-remote-src`), restorable on request.
- **Superadmin tenant page**: add addresses (with optional catch-all) and
  (de)activate them, audited (`mailbox.address_*`). One domain can belong to
  one business only.
- **Tests**: signature (incl. Worker WebCrypto vs app), headers/subjects,
  sanitizer, Worker payload vs the app's schema, webhook decision table,
  defaults-off now also asserts the webhook's 404, and a MySQL suite for
  routing, ingest, idempotency, threading, contact link and tenant isolation.

## Decisions and deviations

1. **No contact is created for an unknown sender.** The plan says "create
   contact (source `email`) if none", but `contacts.phone` is NOT NULL and
   unique per tenant, and an email has no phone. The chat widget hit the same
   wall and chose not to invent phone numbers (schema/chatwidget.ts); same
   here. Unknown senders stay as the thread's `participant_email`; E4 lets a
   user create the contact from the thread (with a phone) or link an
   existing one.
2. **Routing uses a new `mailboxes` table, not `tenant_email_domains`.**
   The plan resolves the tenant "via tenant_email_domains (status verified)",
   but `verified` there means *Resend* verified, which a Cloudflare-only
   domain never is. The superadmin adds the address on the business page
   instead.
3. **The app must use `STORAGE_DRIVER=s3` on the same R2 bucket as the
   Worker.** The Worker doesn't know the tenant, so it writes to
   `email-inbound/…`; the app reads those objects back through its own
   storage driver. `isMailboxConfigured()` now also requires the S3 driver.
4. **Discarded mail is deleted** from R2 (202 = no business owns that
   address). Mail the app rejects as malformed (400) is kept and marked
   failed.
5. **Unread badge / notifications** are left for E4, with the UI.

## Anton sets up by hand (only when going live; nothing needed to merge)

Before merging: run migrations (0043 and 0044) — see docs/DEPLOY.md §2.

Go-live, after E4 is merged:
1. R2 bucket used by the app: `STORAGE_DRIVER=s3` and the `S3_*` vars
   pointed at it (docs/DEPLOY.md). The Worker uses the same bucket.
2. `cd workers/email-inbound && npm install`, edit `wrangler.toml`:
   `bucket_name` = that bucket, `INBOUND_URL` = `https://<crm>/api/v1/email/inbound`.
3. `npx wrangler login`, `npx wrangler secret put EMAIL_INBOUND_SECRET`
   (same value as on Hostinger), `npx wrangler deploy`.
4. Cloudflare dashboard → the test domain → Email Routing → catch-all →
   "Send to a Worker" → `vendercrm-email-inbound`.
5. Superadmin → the business → Casilla de correo → add `contacto@domain`
   (tick "Recibe todo el dominio" if the catch-all should land there) →
   Activar casilla.
6. Send a test email to the address; it appears in the thread tables (the
   Inbox screen is E4).
